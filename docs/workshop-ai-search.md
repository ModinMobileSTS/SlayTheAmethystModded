# 市场 AI 搜索

Android 市场页已接入工坊搜索对话。模型、端点、推理强度、请求超时和凭据来自已有 LLM 设置；每轮使用 `PolicyGatedAgentGateway`、单次执行的 `AgentRequestControl` 和独立的只读工具注册表。市场不会把本地编辑器的工作区、附件或编辑工具传给模型。切换 Tab、打开详情和旋转设备时对话由市场 ViewModel 保留；进程终止后不恢复。

**Android 对话布局**：消息可以从公共标题栏和浮动输入框背后滚过。`LazyColumn` 的内容留白按标题高度和输入框实际高度（含键盘/系统导航区）计算，使首尾消息能完整露出；输入框直接使用模组编辑器的 `AiChatComposer` 和 `FrostedGlassChrome`，跟随启动器的模糊/不透明度设置。底部的「新建对话」创建独立上下文，「对话列表」可切回旧消息和草稿。切换会话会停止原会话中正在进行的检索。

## 实际工具协议

- `search_workshop(query, category?, page?)` 走市场已有的 Steam 搜索链路，限定 appId `646570`，只返回候选 ID、名称、作者和短摘要。每页最多 12 项，每种查询可翻 3 页，每轮最多 6 次不同检索。可根据返回的 `has_more` 翻页，也可换功能词、英文名或 Steam 分类。
- `read_workshop(id, offset?)` 只接收本轮搜索发现、用户提供或近期对话卡片中的 ID。校验原始 Steam 响应的成功状态、实际 ID、游戏和内容载荷，排除失效条目、可识别的合集和仅有列表摘要的降级结果。每轮最多读取 8 个详情；长说明按需读取，每段最多 3200 个字符，不向模型传递完整网页、评论、下载链接或会话数据。
- `cite_workshop(id, quote, match)` 校验引用逐字出现在**本轮实际读到的同一条目原文片段**。成功才签发本轮 `[[mod:N]]` 引用；UI 将其就地渲染成已有市场模组卡片与可展开的出处，下载仍需玩家点击。不存在的引用不能生成卡片。追问保留最近 5 轮对话文本和卡片出处，需要新引用时重新核实。

开启工坊加速时，普通市场与 AI 共用只读 HTTP 路由队列：工坊搜索页、单条详情 API、社区详情页、模组评论分页、更新日志、列表后台元数据补全和批量摘要都将官方线路纳入候选，最多两轮。HTTP `502/503/504` 与读取正文失败可以切换线路；官方返回 `403/429` 不触发这套换线。关闭加速时不启用队列。引用工具不发网络请求。Steam 登录及 CM 兜底、订阅操作、工坊讨论区和下载/图片仍走各自的请求或重试流程。

**为什么要分成三步：**[ReAct（Yao 等）](https://react-lm.github.io/) 展示了让模型根据外部检索结果调整下一步行动的做法；这里用它指导“搜短词 → 查看候选 → 换词或深入详情”，而不是只提交一次自然语言全文查询。[ALCE（Gao 等，EMNLP 2023）](https://aclanthology.org/2023.emnlp-main.398/) 把答案正确性与引用质量分开评估；这里也把“引用确实存在”和“引用足以支持这个需求”分开。前者由程序校验，后者仍依赖模型判断，玩家可展开原文复核。没有把论文中的指标当成本功能的准确率。

## 先试一个容易搜错的例子

输入「想用触屏标记地图节点」。工坊里 *Highlight Paths* 的作者确实写了能标记节点，但原话是 **“Right click on map nodes to highlight them.”** 这能证明右键标记，不能证明触屏可用。

因此助手先说明无法确认触屏支持，再在同一条回复中给出待核实卡片。玩家可以点击匹配依据旁的小三角展开或收起原文，也可以主动去掉触屏条件再追问。

## 界面如何接在市场里

- **入口与动效**：Android 标题统一为「市场」，保留市场图标，不显示副标题。普通搜索和 AI 搜索双按钮始终显示；窄屏缩小市场图标和间距，空间不足时把操作移到下一行。图标 Tab 的选中底色、顶部筛选区收展和两页交接共用一个无弹跳的进度。列表和对话只横移 12 dp 并交叉淡化；顶部搜索收起时，输入框从底部 16 dp 内就位。快速点回可从当前进度反向，关闭系统动画时直接切换。过渡中的旧页面不接收点击。
- **AI 对话**：标题栏以下替换为独立滚动的消息区和固定输入栏；收起筛选、登录提示、工坊列表及启动器 Dock。顶部仍可打开下载中心、切回普通搜索。两边各留一份草稿；切换不清空关键词、筛选、列表位置或对话历史。
- **回复里的模组**：回复由有序的文字块与 `mod_card` 块组成。卡片块只携带工坊 ID 与证据状态；渲染时用同一份已核对的条目生成市场卡片。无有效 ID 不渲染卡片。封面、作者、评分、数量、下载入口与市场一致；原文可展开，标题可打开工坊原页。
- **追问**：先问「想让地图更容易看清」，再点「那触屏能用吗？」会对上一轮候选逐项核实。新回复追加在下方，不覆盖原来的推荐。检索时复用模组编辑器的加载、思考和工具行；每次搜索、读取详情和核对引用都单独显示，可以展开查看入参和结果。停止后保留本轮已显示的记录，重试则重新记录。检索中底部发送按钮变为停止；失败可在原消息重试。

## 怎样得到有依据的结果（正式接入的设计约束）

1. **把描述拆成可检查的要求。** 区分用途、硬条件和偏好，保留否定词。「想标记路线」和「必须能用触屏标记路线」是两次不同的搜索。已有模组名或工坊 ID 时优先核对该条目；“好用的辅助”这样没有具体用途的描述先澄清。
2. **让模型提检索词，让市场给候选。** 将中文俗称、功能词展开成少量中英文短查询，如「地图配色 → 彩色地图 / colored map / map icons」。只在《杀戮尖塔》工坊（appId `646570`）多路检索；分类映射到已有 `WorkshopModCategory`，不把自由文本变成不存在的 Steam 标签。候选按 `publishedFileId` 去重，不从模型记忆补条目、作者或 URL。
3. **列表负责发现，详情负责核实。** 用 `WorkshopService.browse` 获取候选，再用 `getDetails` 核对排在前面的少量候选。每个功能结论须能回指同一 ID 的详情字段或原文片段。中文解释与作者原话分开。合集、跨游戏、失效条目不当作可用模组；全文未取到或字段缺失时标为未知。
4. **按需求排序，不按知名度凑数。** 全部硬条件都有依据的条目在前，再看用途和偏好。热度仅作同等匹配时的辅助。硬条件缺证据的单列为「待核实」；明确冲突的剔除。更新时间用条目元数据；“本周热门”不是“本周更新”。语言、依赖完整性和 Android 兼容性都不能由界面语言、评论或下载量推断。
5. **区别无结果、缺证据和失败。** 首轮无候选可以换同义词，不暗中放宽硬条件；本轮未找到不代表全市场不存在。详情读取受限时说明哪些条目尚未核实；网络中断或限流则保留需求，提供重试及关键词入口。

## 评审走查

| 在原型中尝试 | 应当看到 |
| --- | --- |
| 想让地图更容易看清 | 两个不同做法：*Colored Map* 调整图标颜色；*Highlight Paths* 手动高亮节点。各有自己的原文与工坊 ID。 |
| 想给地图图标换颜色 | 只显示配色条目，不把高亮节点混作同一个功能。 |
| 推荐一个好用的辅助 | 先问想解决什么，选择“配色”和“标记”会进入不同结果。 |
| 想用触屏标记地图节点 | 没有完全匹配；右键不等于触屏。只在玩家点击放宽后才重搜。 |
| 想找能朗读卡牌的模组 | 示例范围内无匹配，有修改需求和关键词回退入口。 |
| 切到「AI：检索失败」后重试；或在加载中点停止 | 重试沿用原问题；停止后不再追加旧结果。 |
