# Steam 订阅自动同步

启动器在启动资源就绪、回到前台以及 Steam 登录状态变化后检查本游戏的订阅库；仅在启动器前台期间发起扫描，不新增后台定时任务。启动/前台触发有时间间隔限制，登录新账号可立即检查。扫描遍历订阅库全部分页，不依赖创意工坊页面是否打开。

应用内订阅经 Steam 确认成功后立即尝试加入现有下载队列。订阅与下载结果分别呈现：下载准备失败不会将成功订阅误报为失败。

## 同步边界

- 只补齐本地缺失内容，不自动更新已有模组。
- 实际本地文件存在时跳过；历史下载完成状态不能单独证明本地文件存在。
- 跳过已排队、运行、暂停、取消中、已取消、失败的任务，以及用户明确删除的下载记录；由用户手动恢复或重试。
- 继续遵循现有下载拦截名单、队列并发限制和下载完成后的导入设置，不强制自动导入或启用模组。
- 只将订阅项加入下载；不隐式订阅或下载其他依赖。需要的依赖可在模组详情中通过已有下载交互处理。
- 退订不删除本地文件。退出登录、切换账号或离开前台后，不再继续旧扫描入队；已经开始的下载沿用现有下载服务控制。
- 单项失败不阻止其他项处理；订阅页读取失败不能视为完整同步成功。

## 验证

离线 JVM 测试覆盖分页、去重、应用过滤、取消传播、失败处理、本地文件判定、任务状态保护以及协调器触发与账号隔离。真实 Steam 登录、Android 前后台切换、通知及文件下载/导入仍需单独进行设备验证，离线测试不代表这些运行时行为已验证。
