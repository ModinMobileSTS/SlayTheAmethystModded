# 独立实现与测试

先读[共同约定](../feature-refactoring/references/handoff.md)，加载
`post-implementation-verification`，复用其实现后测试流程。

## 前提与技术设计关口

核对已确认的业务能力、验收场景、修改范围和独立验证条件。
缺少业务契约时返回 `feature-value-design`，不自行补全需求。
先提出足以实施的职责划分、候选能力接口、状态归属、依赖和测试入口。
重大架构取舍必须先经人类确认；未确认前不修改依赖该决定的实现。
确认范围内的常规实现细节自行处理，不反复索取已有授权。

## 实现边界

- 实现完整业务能力，不一比一移植旧函数，不用固定示例假装实现完整契约。
- 不修改真实业务入口或切换调用方，不增加生产双跑、开关接入或隐式回退。
- 独立测试可直接调用新能力；它不属于真实生产接入。
- 不借用待删除的旧实现承载核心行为。必要共享依赖说明归属并符合确认设计。
- 能力接口仍可在接入讨论中调整，不预先制造大量猜测性的兼容层。
- 实现暴露业务或重大架构问题时返回人类讨论，不暗中更改契约。

## 验证与完成

按 Test-After 补充并执行需求驱动的正常、边界、异常和关键副作用测试。
检查实际 diff，确认真实入口未切换，说明测试入口及与旧实现的依赖关系。
若只能编译或必要行为测试阻塞，报告限制，不能宣称独立能力完整验证。

交接实现位置、候选接口、技术确认依据、测试证据、限制与未决问题，结束后停止。
独立测试通过不代表真实接入成功；下一阶段是 `feature-integration-design`。
