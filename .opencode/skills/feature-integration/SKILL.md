# 新路径接入

先读[共同约定](../feature-refactoring/references/handoff.md)，加载
`post-implementation-verification`。核对确认的业务契约、接入方案、清单和独立验证证据。
缺少关键设计确认时返回 `feature-integration-design`，不自行决定切换范围。

## 接入执行

- 按方案实现/调整新接口、连接真实入口和调用方，装配依赖、状态与生命周期。
- 检查错误传播、资源释放及实际相关的取消、重入和副作用。
- 必要的调用方改动和停用旧路由属于接入；大范围旧实现删除留给下一阶段。
- 清单逐项记录哪些旧路径已不可达、哪些仍被调用、哪些为确认保留的共享能力。
  不把旧文件仍存在当作仍在运行，也不把静态无引用当作全部退出。
- 不用旧实现静默回退掩盖新路径问题。仅可使用确认方案批准的临时机制，
  记录触发条件、证据与下一阶段清理条件。
- 若预定切换入口仍使用旧核心实现，接入尚未完成；不能直接进入删除阶段。

## 接入验证与交接

按 Test-After 添加/更新针对性集成测试，至少执行实际模块的必要编译和行为检查。
通过真实入口或其可控测试边界证明新能力确被调用，并核查关键状态、错误和副作用。
只测新类、只编译或只用调用搜索均不能替代接入行为证据；无法运行时如实标记阻塞。
完整回归可在清理阶段收口，但不能把所有测试拖到最后。

更新接入与清理清单，说明已切换入口、旧路由状态、临时机制、测试结果和限制。
必要接入检查未满足时不得建议直接删除旧路径。交接后停止，下一阶段为
`feature-cleanup-verification`；当前完成不代表整项重构完成。
